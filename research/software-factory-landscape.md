# 「ソフトウェア工場」という言葉の使われ方（2026-10-17）

同じ言葉が、時代と書き手によって違う意味で使われている。大きく 3 つに分けられる。

## 1. 昔からの意味: 決まった手順と再利用で、同じ品質を繰り返し作る

- 日本のソフトウェア工場。日立は 1969 年に始めたとされる（二次資料による）。日立・東芝・NEC・富士通が 1960 年代後半から 70 年代にかけて作った（Cusumano, https://dspace.mit.edu/bitstream/1721.1/2280/1/SWP-3087-24832363.pdf ）。
- Microsoft の Software Factories（2004 年、Greenfield と Short）。特定分野向けの小さな言語（DSL）と、似た製品を系列で作る仕組み（プロダクトライン）が中心。
- 米国防総省のソフトウェア工場。開発・セキュリティ・運用をつないだ自動化の流れ（DevSecOps パイプライン）を指す。Kessel Run や Platform One が例。

共通点は、手順を揃えて部品を使い回し、同じものを繰り返し作れるようにすること。コードを書くのは人のまま。

## 2. AI の狭い意味: 人がコードを書かず、見もしない（L5）

StrongDM の例（https://factory.strongdm.ai/ ）。

- 規則は 2 つ。「人がコードを書いてはならない」「人がコードをレビューしてはならない」。
- 入力は仕様とシナリオ（利用の筋書き）。シナリオはコードの外に置き、エージェントが合わせ込めないようにしている。
- 合否の代わりに「満足度」を使う。何通りも動かしてみて、そのうち利用者を満足させそうなものの割合で測る。
- 「Digital Twin Universe」で外部サービスを模している。Okta、Jira、Slack、Google Workspace の偽物を立て、その上で試す。

## 3. AI の広い意味: 出荷後まで含めて輪を閉じる

Factory 社（factory.com）の説明（https://factory.com/news/software-factory ）。

- エージェント前提の部品をつないだ、端から端までの仕組み。
- 流れは、シグナル（要望や障害の兆し）→ 振り分け → 作る・試す・レビュー・安全確認・出荷 → 本番の監視。監視から新しいシグナルが出て、また最初に戻る。
- 必要な条件として 3 つを挙げる。特定のモデルに縛られないこと、自社の知識を自社で持つこと、使いながら学び続けること。
- エンジニアは工場を作る側に回り、統制・安全・結果に責任を持つ。人がどこまで関わるかは場合による。

BCG は「どの関門にも、承認に責任を持つ人がいる」と書いている（https://www.bcgplatinion.com/insights/the-agentic-software-factory ）。この意味では人の承認は残る。

## 世の中はどこまで来ているか

- PostHog では、PR の約 70% をエージェントが書く。そのうち少なくとも 80% は人がざっと目を通している。完全に人の手を離れた公開例として挙がっているのは StrongDM だけ（https://newsletter.posthog.com/p/software-factories ）。
- Shapiro によると、ほとんどの人は L3 で止まる（https://www.danshapiro.com/blog/2026/01/the-five-levels-from-spicy-autocomplete-to-the-software-factory/ ）。

Shapiro の 5 段階（同じ URL）:

- L0: 人が全部書く。AI は検索や補完の受け入れ程度。
- L1: 単体テストの作成など、区切った小さな作業を AI に任せる。
- L2: AI と同僚のように組んで書く。
- L3: AI が書き、人はループの中にいてコードを読み続ける。「生活が差分になる」。ほとんどの人はここで頭打ちになる。
- L4: 人は仕様を書いて任せ、あとでテストが通ったかを確かめる。
- L5: Dark Factory。仕様をソフトウェアに変える中の見えない箱。人は要らない。

## claude-org の位置

claude-org は、Claude Code のワーカーを並べて開発する手元の仕組み。だいたい L3〜L4 にいる。

- CI（自動テスト）が通れば自動でマージする。
- 仕事を投入するのと、判断が要る場面を決めるのは人。

作る側の輪（依頼 → 作る → 試す → マージ）は持っている。持っていないのは次の 2 つ。

- 出荷後の輪。本番を監視し、そこから次の仕事を作る流れ。
- 計測。費用や品質を数字で取る仕組み。

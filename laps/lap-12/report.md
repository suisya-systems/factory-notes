## 工場の不具合 factory#62（画面の期待値の比べ方の非対称）

- **何が起きたか。** 工場は、画面を読むときに、各要素の文字（入力欄はその値）の空白を畳んで前後を切る（`src/browser.ts` の SNAPSHOT。`.replace(/\s+/g, ' ').trim()`）。一方、期待値の側はそのまま比べていた（`src/scenario.ts` の `checkStep` → `subset`）。前後に空白がある文字や、空白が続く文字を期待する画面の段は、アプリが正しくても決して通らない。
- **どこで見つけたか。** ゲート `screen` の読み（Codex のシナリオ 4 組）で見つけた。該当したのは Codex のシナリオの 8 段・4 本（task-board-cx-p の `form-errors-and-success` と `ui-filter-commit-and-hidden-add`、expense-wizard-cx-p の `wizard-edit-submit-reset` と `report-list-filter-and-balances`）で、Claude のシナリオには 0 段だった。どれも、入力した文字（`"  Emi  "` など）がそのまま入力欄に残ることを確かめる段で、シナリオの意図は正しい。最初に落ちる段が早いので、4 本ともその後の確認が丸ごと失われるところだった。
- **直し方。** PR #63（da3de63）で、画面の段の期待値の文字にも同じ畳み込みをかけた。API の段は変えていない。モデルは呼んでいない。承認するシナリオの中身も変わらないので、ゲート `screen` の版はそのままである。build の前に直したので、採点し直しは要らなかった。
- **直した後。** 4 本のうち 3 本は 4 build とも通った。`ui-filter-commit-and-hidden-add` は、空白を確かめる段 8 を通り、後の段 10 で上の `notice` の点で落ちた（4 中 3 build）。

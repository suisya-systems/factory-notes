# laps

工場を実際に回した記録（lap）の置き場。lap ごとに、事前に書いた手順書（`lap-N-runbook.md`）と結果の報告（`lap-N-report.md`）がある。lap 5 と lap 6 は、事前登録（`prereg.json`）、判定用のスクリプト、参照アプリ（`refapps/`）もディレクトリ `lap-5/` と `lap-6/` に置いてある。`lap-6/lap.json` は lap 6 の手順を、工場の `lap` コマンドが読む定義ファイルの形で書いたもの。lap 7 は `lap` コマンドで流した最初の周で、手順書・報告・事前登録・定義ファイル・判定用のスクリプトをすべてディレクトリ `lap-7/` に置いた（報告は `lap-7/report.md`）。lap 7 の記録は、工場のリポジトリから移したものではなく、ここに直接置いた。lap 8 の記録は、工場のリポジトリの作業用フォルダ（git 管理外の `docs/lap-8/`）から写して、ここに直接置いた。報告は `lap-8/report.md`。lap 8 の結果は、試験を採点する仕組み（工場の `src/scenario.ts`）の不具合を直したあとに採点し直したもので、報告には採点し直す前と後の両方の数字を載せてある。lap 9 の記録は、lap 8 と同じく工場のリポジトリの作業用フォルダ（git 管理外の `docs/lap-9/`）から写して、`lap-9/` に置いた。報告は `lap-9/report.md`。`prereg.template.json` は実走前に登録した版（6 依頼分の雛形）のままで、実走で使った確定版は `prereg.json` が持つ。lap 9 は依頼の未決の多さを 2 段（曖昧版・厳密版）にして測る周で、予備選別と本番の集計、事前登録の確定版（`prereg.json`）、判定用の `arms.ts`（書き直した組を同じ系統として読むよう直したもの）を置いてある。結果は、試験の採点で JSON のキーの中の `"{{name}}"` が置き換わらない工場の不具合を直して採点し直したあとの数字で、報告には直す前と後の両方を載せてある。主の判定は「決められない」で、採点し直すと 6 依頼がすべて天井になり、本番に回る依頼が無かった。lap の定義は工場のリポジトリの `examples/lap-9.json`。lap 10 は規則の絡みで難しさを作る周で、予備選別で 4 依頼すべてが天井になり、本番を流さずに閉じた。手順書・報告・選別の要約は `lap-10/` にある（報告は `lap-10/report.md`）。lap 11 は外部サービスの偽物で難しさを作る周で、これも予備選別で 4 依頼すべてが天井になり、本番を流さずに閉じた。設計と手順書、定義の道具、選別の要約と報告は `lap-11/` にある（報告は `lap-11/report.md`）。`lap-12/` は 12 周目の前の準備で、ブラウザの画面を周で使う前の見積もり（時間・費用・判定の側の揺れ、factory#54）を `lap-12/browser-estimate.md` に、その計測の道具と出力を `lap-12/browser-estimate/` に置いた。12 周目の設計（ブラウザの画面で難しさを作る周の手順書）は `lap-12/runbook.md`、予備選別の規則と事前登録の雛形は `lap-12/screen.json` と `lap-12/prereg.template.json` にある。12 周目も予備選別で 4 依頼すべてが天井になり（揺れは 0）、本番を流さずに閉じた。報告は `lap-12/report.md`。`calibrate-80/` は、作る役の合格率がおよそ 80 % になる条件を予備選別だけで探す較正の設計（`calibrate-80/design.md`）で、2×2 の周ではない。作る役 opus のまま依頼を大きくする系列と、作る役を sonnet にする系列を並行に回す。前の系列の L1 の合わせた依頼 3 本（`calibrate-80/requests/`）、その規則と絡み（`calibrate-80/rules.json`）、予備選別の lap 定義（`calibrate-80/cal80-o1.json`）と、その説明（`calibrate-80/l1-requests.md`）も置いた。L1 がすべて 90 % 以上だったので、L1 の 3 本に同じ周の 1 本を足した L2 の依頼 3 本（同じ `calibrate-80/requests/`）と、その lap 定義（`calibrate-80/cal80-o2.json`）と説明（`calibrate-80/l2-requests.md`）も置いた。L1 の結果（opus と、同じ依頼に sonnet を当てた段 S3）の途中報告は `calibrate-80/l1-report.md` にある。L2 の結果（同じく opus と段 S3 の sonnet）の途中報告は `calibrate-80/l2-report.md` にあり、L2 もすべて 90 % 以上だったので、系列 O は「3 本を合わせても天井」で閉じた。L3 と Haiku の世代の作る役は、オーナーに諮る項目として残っている。

これらは 2026-10-18 に工場のリポジトリ（suisya-systems/factory）の `docs/` から、コミット 4558260 の時点の内容のまま移した。工場のリポジトリは英語の本文と機能だけを持つ方針にしたため。

## 読むときの注意

- 本文中の `docs/lap-N/...` や `src/...` といったパスは、工場のリポジトリのパス。移す前の内容をそのまま残している。該当するコードは https://github.com/suisya-systems/factory/tree/4558260979271cf02890e172830f73fa7e6aaf53 で読める。
- 工場のリポジトリ内のファイル（README と `requests/`）を指していたリンクは、上のコミットの GitHub の URL に書き換えた。lap の記録どうしのリンクは、移した後も同じ相対位置でたどれる。
- `lap-5/refapps/*.ts`、`lap-6/*.ts`、`lap-8/entrance.ts` は工場の `src/` を相対パスで読み込む。動かすときは、上のコミットの工場のリポジトリの `docs/` に置き直す。
